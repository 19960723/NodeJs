# RESTful API 标准规范

## HTTP 状态码使用规范

### 成功响应 (2xx)

- **200 OK**: 请求成功，返回数据
- **201 Created**: 资源创建成功
- **204 No Content**: 请求成功，无返回内容（如删除操作）

### 客户端错误 (4xx)

- **400 Bad Request**: 请求参数错误
- **401 Unauthorized**: 未授权，需要登录
- **403 Forbidden**: 权限不足
- **404 Not Found**: 资源不存在（URL路径不存在或资源ID不存在）
- **409 Conflict**: 资源冲突（如名称重复）

### 服务器错误 (5xx)

- **500 Internal Server Error**: 服务器内部错误

## 响应格式标准

### 成功响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    // 具体数据
  }
}
```

### 错误响应格式

```json
{
  "code": 404,
  "message": "资源不存在"
}
```

### 分页响应格式

```json
{
  "code": 200,
  "message": "获取数据成功",
  "data": {
    "list": [
      // 数据列表
    ],
    "pagination": {
      "page": 1,
      "pageSize": 10,
      "total": 100,
      "totalPages": 10
    }
  }
}
```

## 业务状态码 vs HTTP状态码

- **HTTP状态码**: 表示HTTP协议层面的状态
- **业务状态码**: 表示业务逻辑层面的状态，统一放在响应体的`code`字段中

### 状态码映射规则

| HTTP状态码 | 业务状态码 | 说明       |
| ---------- | ---------- | ---------- |
| 200        | 200        | 成功       |
| 201        | 200        | 创建成功   |
| 204        | 200        | 删除成功   |
| 400        | 400        | 参数错误   |
| 401        | 401        | 未授权     |
| 403        | 403        | 权限不足   |
| 404        | 404        | 资源不存在 |
| 409        | 409        | 资源冲突   |
| 500        | 500        | 服务器错误 |

## 具体场景处理

### 1. 查询单个资源

- **资源存在**: HTTP 200 + 业务状态码 200 + 数据
- **资源不存在**: HTTP 200 + 业务状态码 404 + data为null

### 2. 查询资源列表

- **有数据**: HTTP 200 + 业务状态码 200 + 数据列表
- **无数据**: HTTP 200 + 业务状态码 200 + 空列表

### 3. 创建资源

- **创建成功**: HTTP 201 + 业务状态码 200 + 创建的资源
- **参数错误**: HTTP 400 + 业务状态码 400
- **资源冲突**: HTTP 409 + 业务状态码 409

### 4. 更新资源

- **更新成功**: HTTP 200 + 业务状态码 200 + 更新后的资源
- **资源不存在**: HTTP 404 + 业务状态码 404 (因为要更新的资源ID不存在)
- **参数错误**: HTTP 400 + 业务状态码 400

### 5. 删除资源

- **删除成功**: HTTP 204 (无响应体)
- **资源不存在**: HTTP 404 + 业务状态码 404 (因为要删除的资源ID不存在)

## 错误处理最佳实践

1. **统一错误格式**: 所有错误响应都使用相同的JSON结构
2. **明确的错误信息**: 提供清晰、可操作的错误信息
3. **适当的HTTP状态码**: 使用符合RESTful标准的HTTP状态码
4. **业务状态码**: 在响应体中提供业务层面的状态码
5. **错误分类**: 区分客户端错误和服务器错误

## 示例

### 正确的响应示例

```javascript
// 获取资源成功
GET /api/examples/1
HTTP 200
{
  "code": 200,
  "message": "获取示例详情成功",
  "data": {
    "id": 1,
    "name": "示例1",
    "status": "active"
  }
}

// 资源不存在
GET /api/examples/999
HTTP 200
{
  "code": 404,
  "message": "not found",
  "data": null
}

// 创建资源成功
POST /api/examples
HTTP 201
{
  "code": 200,
  "message": "创建示例成功",
  "data": {
    "id": 2,
    "name": "新示例",
    "status": "active"
  }
}

// 参数错误
POST /api/examples
HTTP 400
{
  "code": 400,
  "message": "示例名称不能为空"
}
```

### 错误的响应示例

```javascript
// ❌ 错误：查询不到数据时使用404
GET /api/examples/999
HTTP 404
{
  "code": 404,
  "message": "示例不存在"
}

// ✅ 正确：查询不到数据时应该返回200，但业务状态码为404
GET /api/examples/999
HTTP 200
{
  "code": 404,
  "message": "not found",
  "data": null
}
```
